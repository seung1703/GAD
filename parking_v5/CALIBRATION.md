# 주차 미션 실측 가이드

`config.py` 값들을 **어떤 순서로, 어떻게** 재는지. 위에서부터 순서대로 하세요 —
뒤 항목이 앞 항목에 의존합니다.

준비물: 줄자, 마스킹테이프, 실제 주차차량 2대.
실행은 conda env `drive` 로: `conda run -n drive python <스크립트>`

---

## 0단계. 가장 먼저 — 이 둘이 틀리면 나머지가 전부 무의미

### 0-1. `MOUNT_OFFSET_DEG` (라이다 장착 각도)

라이다가 **가로로** 달려 있어서 원시각과 차체 방향이 90도 단위로 어긋나 있습니다.

상수가 **두 개**입니다. 회전(`MOUNT_OFFSET_DEG`)과 각도 증가 방향
(`LIDAR_ANGLE_DIR`). 회전만으로는 좌우를 못 바꿉니다 — 좌우 교환은 거울 반전이라서.

1. 차 뒤(후진 진행 방향)에 물체를 두고 `python3 lidar_scope.py` 로
   그 물체의 **원시각 A** 를 읽습니다.
2. `MOUNT_OFFSET_DEG` 를 넣습니다:
   `LIDAR_ANGLE_DIR = +1` 이면 `-A`, `-1` 이면 `+A`.
3. `python3 frames.py` 로 표를 보고 **전진/후진**이 맞는지 확인합니다.
4. 전진·후진은 맞는데 **좌우만 반대**면 `LIDAR_ANGLE_DIR` 부호를 뒤집고
   2번을 다시 합니다 (부호를 바꾸면 `MOUNT_OFFSET_DEG` 도 부호가 바뀝니다).

현재 실측값은 `A = 270`, 라이다가 각도를 반대로 세므로
`LIDAR_ANGLE_DIR = -1`, `MOUNT_OFFSET_DEG = 270`. 이때 방향 매핑:

| 원시각 | 차체 방향 |
|---|---|
| raw 0° | 좌측 |
| raw 90° | 전진 |
| raw 180° | 우측 |
| raw 270° | 후진 |

**검증**: `python3 frames.py` 로 표를 출력하고, `lidar_scope.py` 화면의 방향 라벨
4개(우측/전진/좌측/후진)가 실제 방향과 맞는지 눈으로 확인합니다.
여기가 틀리면 아래 전부 헛수고입니다.

> 섹터(우측 탐지, 좌·우 판정, 후방 부채꼴)는 **차체 기준으로 정의**돼 있어서
> `MOUNT_OFFSET_DEG` 만 고치면 전부 따라 돕니다. 예전엔 원시각을 상수로 적어둬서
> 재장착 때 같이 안 고쳐지는 버그가 두 번 났습니다
> (`REAR_GATE_SECTORS` 가 후방 대신 좌측을 가림).

### 0-2. `PARK_STEER_SIGN` (조향 극성)

**★이거 틀리면 주차가 아니라 사고입니다★**

1. 차를 바퀴가 안 닿게 받침대에 올립니다.
2. `python3 main_parking.py --run` 으로 띄우고 `s` → 우측에 손을 대서 트리거,
   `SWING_OUT` 까지 갑니다.
3. `SWING_OUT` 은 **좌 풀조향**이어야 합니다. 우측으로 꺾이면 부호를 반대로.

`drive`/`obstacle` 미션은 실측 결과 `steer_sign = -1` 입니다. 같은 차·같은 펌웨어라
`PARK_STEER_SIGN = -1` 이 출발점입니다.

## 1단계. 라이다 설치값 (차 세워두고, 5분)

### 1-1. `BLOCKED_SECTORS_RAW` (차체가 영구히 가리는 각도)

차를 사방 3m 이상 트인 곳 한가운데 세웁니다.
```bash
python3 lidar_scope.py --bin 5
```
30초쯤 두고 **Ctrl-C**. 구간별 표에서 **유효율 20% 미만**이 가림 후보이고,
마지막에 `BLOCKED_SECTORS_RAW = [...]` 줄이 출력되니 그대로 붙여넣습니다.

**원시각**으로 적는 유일한 상수입니다(차체 가림은 라이다 장착에 붙는 성질).
그래서 이름에 `_RAW` 가 붙어 있습니다.

### 1-2. `MIN_VALID_DIST` (차체 반사 컷)

같은 표에서 "근거리반사"로 표시된 구간의 최소거리보다 조금 크게.
- `REAR_EMERGENCY_DIST`(120mm)보다는 **커야** 합니다.
- 300mm 는 넘기지 마세요 (실제 물체를 버리기 시작합니다).
- 기본 150.

> `REAR_EMERGENCY_DIST(120) < MIN_VALID_DIST(150)` 은 의도된 것입니다.
> 후방 비상정지는 원시 스캔을 직접 읽어 이 마스크를 **우회**합니다 —
> 마스크를 태우면 정작 위험한 물체를 "차체 반사"로 버리기 때문입니다.

### 1-3. 섹터 반폭 `DETECT_HALF_DEG` / `FLANK_HALF_DEG` / `REAR_FAN_HALF_DEG`

`lidar_scope.py` 를 켠 채 차를 손으로 밀면서 주차차량이 음영 섹터에 들어오는지 봅니다.
- `DETECT_HALF_DEG`(기본 20): **좁을수록** 트리거가 걸리는 *위치*가 재현성 있습니다.
  넓히면 멀리서·비스듬히도 걸려서 매번 다른 지점에서 꺾습니다.
- `FLANK_HALF_DEG`(기본 35): 후진 중 옆차가 이 섹터에 들어와야 "봤음"으로 잡힙니다.
- `REAR_FAN_HALF_DEG`(기본 35): 후방 비상정지 감시 범위.

### 1-4. `FLANK_NEAR_DIST` (옆에 차가 "있다" 판정 반경)

```bash
python3 main_parking.py --calib
```
차를 슬롯 옆으로 손으로 밀면서 `flank_left` / `flank_right` 의 `d=` 값을 읽고,
그보다 넉넉하게 잡습니다 (기본 900mm).

## 2단계. 주행 튜닝 (실제로 굴려야 함, 20분)

### 2-1. 속도 `FWD_SPEED` / `REV_SPEED`

바닥에서 **확실히 굴러가는 가장 낮은 PWM**. 기본 45.
너무 빠르면 관성 오버슛이 커져 2단계 종료가 늦게 걸립니다.

### 2-2. `SWING_TARGET_DEG` (2단계 종료 회전량) ★가장 중요★

기하 목표는 45도지만 정지 명령 후에도 관성으로 더 도니 그보다 낮게. 기본 40.

1. `--record run1.pkl` 로 한 번 돌립니다.
2. 상태줄 `swing_out 회전 NN/40도` 를 보고 멈춘 뒤의 자세를 확인합니다.
3. 슬롯 정면을 지나쳤으면 낮추고, 덜 돌았으면 올립니다.

> 이 단계는 벽면각 **절대값**이 아니라 **변화량 누적**으로 판정합니다.
> 절대값으로 하면 이웃 차량의 *측면*을 잡은 프레임에서 시작값이 이미 90°라
> 즉시 종료됩니다(확인된 버그). 자세한 이유는 README 참고.
> 상태줄의 `(면교체 무시 N)` 이 계속 늘면 벽 추적이 불안정하다는 뜻입니다.

### 2-3. `REVERSE_ALIGN_TOL` (후진 중 바퀴 푸는 시점)

풀락으로 끝까지 후진하면 차가 정렬을 지나쳐 계속 돌아 비스듬히 박힙니다.
옆차 벽면이 후진축과 이 오차(도) 안으로 평행해지면 바퀴를 중립으로 풉니다. 기본 12.
- 로그의 `슬롯과 정렬(dev=NN도) → 바퀴 중립` 이 너무 이르면 값을 줄입니다.
- `0` 으로 두면 끝까지 풀락 후진 (사양 원문 동작).

### 2-4. `EXIT_TURN_S` (8단계 우회전 시간)

원래 진행 방향으로 되돌아가는 시간. 회전반경·노면·배터리에 따라 달라져 **실측**입니다.
기본 2.5초. 차를 슬롯에서 꺼내 놓고 `EXIT_TURN` 만 반복 관찰하며 ~90도 나오게 맞춥니다.

### 2-5. 유지시간 `TRIGGER_HOLD_S` / `FLANK_CLEAR_HOLD_S`

노이즈 한 프레임에 오발동하지 않게 하는 값. 기본 0.15 / 0.20초.
오발동이 잦으면 늘리고 반응이 느리면 줄입니다.
프레임 수가 아니라 **초**라서 `LOOP_HZ` 를 바꿔도 의미가 안 변합니다.

## 검증 루프

```bash
# 1) 방향부터
conda run -n drive python frames.py
conda run -n drive python lidar_scope.py

# 2) 조향중립 직진 + 인식 화면
conda run -n drive python main_parking.py --straight

# 3) 한 번 녹화 (손은 ESC 위에)
conda run -n drive python main_parking.py --run --record run1.pkl

# 4) 실내에서 몇 번이고 다시 돌려보며 튜닝
conda run -n drive python main_parking.py --replay run1.pkl
```

실패한 런도 `.pkl` 이 남으므로 오프라인에서 다시 돌릴 수 있습니다.
`Space` 로 일시정지하면 그 프레임에서 화면이 멈춰 인식 결과를 뜯어볼 수 있습니다.

## 시간이 없을 때 우선순위

1. `MOUNT_OFFSET_DEG` — 방향. 틀리면 전부 무의미
2. `PARK_STEER_SIGN` — 틀리면 사고
3. `SWING_TARGET_DEG` — 주차 성공/실패를 직접 결정
4. `EXIT_TURN_S` — 나오는 동작
5. `FLANK_NEAR_DIST` / `BLOCKED_SECTORS_RAW`
6. 나머지는 기본값으로 대체로 굴러갑니다

## 알려진 미해결 (실차에서 확인해야 함)

- **0단계 트리거에 거리 조건이 없습니다.** 우측 섹터에 `MAX_DISTANCE`(3000mm) 안으로
  뭐든 잡히면 걸립니다. 너무 이르게 꺾이면 `MAX_DISTANCE` 를 줄이는 게 가장 짧은
  수정입니다. 또 **차를 출발시키는 사람이 차 우측에 서 있으면 즉시 트리거됩니다** —
  뒤에 서세요 (후방 raw 270 은 탐지 섹터가 아닙니다).
- **3단계 "양옆 소멸"의 성립 조건.** 슬롯 950mm 에 차가 들어가면 옆 벽이
  `MIN_VALID_DIST`(150mm) 안으로 들어와 "사라지는" 원리에 의존합니다. 차폭이 좁아
  벽이 200~300mm 로 남으면 조건이 영영 안 걸리고 `REVERSE_TIMEOUT_S` 가 실제 종료
  조건이 됩니다. `--calib` 의 `d=` 값으로 먼저 확인하세요.
- **후진이 한 단계입니다.** 원래는 정렬 후 바퀴를 풀고 직진 후진하는 2단계였는데
  사양이 한 단계로 합쳐졌습니다. `REVERSE_ALIGN_TOL` 로 바퀴 푸는 동작만 살려뒀습니다.
